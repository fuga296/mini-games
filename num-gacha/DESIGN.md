# NUM GACHA 設計メモ

## 1. ルールのまとめ

| 項目 | 値 | 設定名 (`logic.js` の `CONFIG`) |
|---|---|---|
| 出る数字 | 1 〜 9,007,199,254,740,991 (`Number.MAX_SAFE_INTEGER`) | — |
| 更新間隔 | 12時間 (端末の現地時刻 0:00 / 12:00) | `refreshHours` |
| 1更新あたりの回数 | 5回 (更新時に5回に戻る。貯まらない) | `pullsPerRefresh` |
| 繰り上がり | 同じ数字が10枚で、1つ上の数字を1枚得る | `carryThreshold` |
| 分布の形 | P(X ≥ n) = n^(−α)、α = 0.28 | `alpha` |
| 上限超えの扱い | 最大値に張り付く (clamp) | `overflow` |

遊び方の前提として、毎回の更新で回す人は **1日10回 (年 3,653 回)**、1日1回だけ開く人は **1日5回 (年 1,826 回)** と考える。

## 2. 分布

### 2.1 式

連続のべき乗分布 (パレート分布) を切り捨てて整数にする。

```
U  = (0, 1] の一様乱数 (53bit)
X  = floor( U^(−1/α) )      … P(X ≥ n) = n^(−α)
X ≥ MAX なら X = MAX         … 上限を超えた分はすべて最大値に乗る
```

ちょうど n が出る確率は

```
P(X = n)   = n^(−α) − (n+1)^(−α)     (1 ≤ n < MAX)
P(X = MAX) = MAX^(−α) = 1 / 29,328   (α = 0.28)
```

- 1 が最も出やすい (17.64%)。2 が 8.84%、3 が 5.69%、10 が 1.38%。
- 桁が1つ増えるごとに出る確率は 10^(−α) ≈ **0.525 倍** (ほぼ半分) になる。
- 桁ごとの確率がほぼ倍々で減るので、「次の桁に届いた」という体験が数か月〜数年の単位で続く。

### 2.2 「最大値」についての解釈

「大きいほど出にくい」を **1つ1つの数字について厳密に** 守ると、最大値の確率は 1/MAX ≈ 1.1×10^(−16) 以下になる。
(9×10^15 個の数字の確率がどれも MAX 以上で、合計が1を超えられないため。)
これでは「数年遊べば一度出るかどうか」という条件と両立しない。

そこで次のように解釈した。

- 「大きいほど出にくい」は **桁 (レア度) の単位で** 守る。1〜15桁、16桁 (最大値以外) の順にどれも前の桁より出にくい。
- 分布の裾 (MAX を超える部分) を最大値に集める。最大値は「上限に張り付いた数字」として特別な確率 1/29,328 を持つ。
- そのため、最大値1つの確率 (1/29,328) は、最大値以外の16桁すべての合計 (1/34,484) より少しだけ高い。ここだけが「1つ1つの数字」の順序の例外になる。

代替案 (`overflow: 'reroll'`) にすると例外はなくなるが、最大値は事実上出なくなる (約 10^(−17))。

### 2.3 α = 0.28 にした理由

条件「毎日遊んで数年続けた人が、一度出るかどうか」を「数年 = 5〜10年で、出る人と出ない人が半々くらい」と読んだ。

| α | 最大値の確率 | 1日10回で平均何年 | 5年で1回以上 (10回/日) | 10年 (10回/日) | 10年 (5回/日) | 1 の確率 |
|---|---|---|---|---|---|---|
| 0.25 | 1/9,742 | 2.7年 | 85% | 98% | 85% | 15.9% |
| 0.26 | 1/14,067 | 3.9年 | 73% | 93% | 73% | 16.5% |
| **0.28 (採用)** | **1/29,328** | **8.0年** | **46%** | **71%** | **46%** | **17.6%** |
| 0.30 | 1/61,147 | 16.7年 | 26% | 45% | 26% | 18.8% |
| 0.32 | 1/127,488 | 34.9年 | 13% | 25% | 13% | 19.9% |

- 0.28 は「毎回回す人で5年なら半々弱、10年なら7割。1日1回の人は10年で半々弱」で、条件に一番近い。
- 0.25〜0.26 は数年でほぼ全員に出てしまい「ギリギリ」感が弱い。0.30 以上は「10年でも半分以下」で、ほとんどの人には一生出ない。

### 4.3 読み取れること

- **最大値**: 毎回回す人で 5年 46%・10年 71%、1日1回の人で 10年 46%。「数年続けて一度出るかどうか」に合う。
- **繰り上がり**: 小さい数字ほどよく出るので、繰り上がりは主に 1〜数百で起きる。10年で約3,000回。
  繰り上がりで新しく解放されるのは「出にくい中くらいの数 (数十〜数百)」の穴埋めが中心で、これが 2〜3桁を全部そろえる手段になる。
  連鎖 (1→2→3…) も起きるが、10枚ずつ必要なので1段ごとに約1/10になり、大きな数字までは届かない (10年で中央値 443)。
- **コレクション**: 10年で約5,700種。1日10回なら、1桁・2桁は1年でほぼ全部そろい、3桁 (900種) は10年で大部分 (確認時の例: 852種) が埋まる。4桁以上は「点在」になるので、画面では未解放の連続を省略して表示する。

## 5. コレクション画面の省略方法 (2案、切り替え可)

全 9×10^15 マスは並べられないので、2つの見せ方を用意した。画面上部のボタンで切り替え、選んだ方は保存される。

### 案A: 桁ごとに折りたたむ (初期表示)

- 1桁〜16桁の16個の折りたたみ。見出しに「解放数 / その桁の総数」と進み具合のバーを出す。
- 開くと、1〜2桁 (99個以下, `UI.fullGridMax`) は未解放も含めて全マスを表示。
- 3桁以上は、解放済みの数字だけマスで出し、間の未解放が **4個以上続くところは「🔒 a〜b 未解放 n 個」の1行** にまとめる (`UI.gapCollapse = 3`)。3個以下の小さな穴は未解放マスとして見せる (あと少しで埋まる感じが見える)。
- 解放済みが多い桁は 240種ずつ「さらに表示」(`UI.pageSize`)。
- 長所: 自分が持っている数字が一覧で見やすい。短所: 未解放の「広さ」は数字でしかわからない。

### 案B: 10進ズーム

- 最初は16桁分のタイル。タップすると、その範囲を10等分 (先頭の桁は 1〜9 の9等分) したタイルに絞り込む。表示は `3,4xx,xxx` のように、決まっていない桁を x で表す。
- 各タイルに「解放数 / 範囲の総数」とバー。何も持っていない範囲は暗い点線のタイル (未解放)。
- 最後の段 (10個) で数字のマスになる。どんな深さでも1画面は最大10タイル。パンくずが長くなったら途中を「…」に省略。
- 長所: 未解放の場所も含めて、9千兆の空間のどこに自分の数字があるかがわかる。短所: 持っている数字を見るのに何度かタップが必要。

## 6. 時刻と保存

- 更新番号 = floor((端末の現地時刻のミリ秒) / 12時間)。番号が前回より大きくなったら回数を5に戻す。
- 端末の時計を戻した場合は番号が小さくなるので、何もしない (回数は増えない)。進めた場合は回復してしまう。サーバーがないので防げない (README に記載)。
- 保存は `localStorage` の `numGacha.v1` 1つ。数字ごとに「手持ち (0〜9)・累計枚数・初入手時刻」を持つ。
- 抽選は `crypto.getRandomValues` の53bit (ない環境では `Math.random`)。

## 7. 決めた値と代替案

| 値 | 採用 | 理由 | 代替案 |
|---|---|---|---|
| α | 0.28 | 最大値が10回/日で平均8年 (§2.3) | 0.26 (約4年、出やすめ) / 0.30 (約17年、より伝説的) |
| 上限超え | clamp | 最大値を実際に出せる唯一の方法 | reroll (数字ごとの単調性を厳密に守る。最大値は事実上出ない) |
| 更新時刻 | 現地 0:00 / 12:00 | 「12時間ごと」を時計の区切りにすると、残り時間がわかりやすい | 最後に回した時刻から12時間 (人によって時刻がずれる) |
| 最大値の繰り上がり | なし (枚数だけ増える) | 上限より上の数字は存在しない | 10枚で「MAX+」の称号を出す |
| レア度の区切り | 1/2/3/4-5/6-8/9-12/13-16桁+MAX | 確率がおおむね 1/2→1/4→1/8→1/10→1/29→1/188→1/2,485 と開き、各色が数か月〜数年ごとに出る | 桁ごとに16色 |
| 未解放の省略 | 4個以上の連続を1行に | 3桁の帯でも「あと少し」の穴は見え、長い空白は1行になる | 常に1行にまとめる (`gapCollapse: 0`) |
