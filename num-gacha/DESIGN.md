# NUM GACHA 設計メモ

## 1. ルールのまとめ

| 項目 | 値 | 設定名 (`logic.js` の `CONFIG`) |
|---|---|---|
| 出る数字 | 1 〜 9,007,199,254,740,991 (`Number.MAX_SAFE_INTEGER`) | — |
| 更新間隔 | 12時間 (端末の現地時刻 0:00 / 12:00) | `refreshHours` |
| 1更新あたりの回数 | 5回 (更新時に5回に戻る。貯まらない) | `pullsPerRefresh` |
| 繰り上がり | 同じ数字が10枚で、1つ上の数字を1枚得る | `carryThreshold` |
| 分布の形 | 桁(段)ごとの確率 P(k) ∝ exp(−c·(k−1)^7)、同じ桁の中は等確率 | `digitShape` |
| 最大値の確率 | 1/30,000 (c をこれに合わせて自動で決める) | `maxOdds` |

遊び方の前提として、毎回の更新で回す人は **1日10回 (年 3,653 回)**、1日1回だけ開く人は **1日5回 (年 1,826 回)** と考える。

## 2. 分布

### 2.1 考え方: 桁を先に決め、同じ桁の中は等確率

数字そのものではなく **桁 (段)** を先に決め、同じ桁の中は **どの数字も同じ確率** にする。

```
段  1 = 1桁 (1〜9)
 …
段 16 = 16桁 (1000兆〜MAX−1)
段 17 = 最大値 9,007,199,254,740,991 だけ

P(段 k) ∝ exp( −c · (k−1)^s )        s = 7  (digitShape)
c は「P(段 17) = 1/30,000」になるように二分法で自動で決める (maxOdds)
P(ちょうど数字 n) = P(n の段) ÷ (その段の数字の個数)
```

- 最大値 (段 17) も他の桁と **同じ式の1項** で、専用ルールはない。maxOdds を決めると c が決まり、そこから全桁の確率が出る。
- 抽選は2回の乱数: ① 段を選ぶ → ② 段の中から一様に選ぶ。
- s が大きいほど、前半 (小さい桁) は平らで、後半に急に出にくくなる。s = 1 なら等比 (1桁上がるごとに一定倍) になる。

### 2.2 なぜこの形か

- **1桁を 5〜10% にしたい** (同じ数字ばかり出るとマンネリする)。1桁が約8.6%、2桁・3桁… も約8.6%で、1〜8桁は **ほぼ横ばい (8.4〜8.6%)**。出る桁がばらけ、同じ数字が続きにくい。
- 一方で **最大値は数年に一度** にしたい。小さい桁を平らにしたまま、最大値 (17段目) まで同じ比で減らすと、最大値が数%で出てしまう (1桁を7%、全桁を一定倍にすると最大値は約5%)。
- そこで「前の桁に対する比」を桁ごとに強める (後半ほど急に下がる) 形にした。比は 1.00 (〜7桁) → 0.98 (8桁) → 0.96 → 0.92 → 0.86 → 0.76 → 0.62 → 0.46 → 0.29 → 0.15 (16桁) → 0.058 (最大値)。最大値に向かって自然に絞られる。
- 同じ桁が等確率なので、レア度 (桁で色分け) と一致する。

### 2.3 最大値 1/30,000 にした理由

条件「毎日遊んで数年続けた人が、一度出るかどうか」を「5〜10年で、出る人と出ない人が半々くらい」と読んだ。

| 最大値の確率 | 10回/日で平均何年 | 1年 | 5年 | 10年 | 10年 (5回/日) |
|---|---|---|---|---|---|
| 1/10,000 | 2.7年 | 31% | 84% | 97% | 84% |
| 1/20,000 | 5.5年 | 17% | 60% | 84% | 60% |
| **1/30,000 (採用)** | **8.2年** | **11.5%** | **45.6%** | **70.4%** | **45.6%** |
| 1/60,000 | 16.4年 | 6% | 26% | 45% | 26% |
| 1/100,000 | 27.4年 | 4% | 17% | 31% | 17% |

- 1/30,000 は「毎回回す人で5年なら半々弱、10年なら7割。1日1回の人は10年で半々弱」で、条件に一番近い。
- `maxOdds` を変えると c が自動で合い直るので、他の桁の確率も連動して変わる。

|---|---|---|---|---|---|---|

### 4.3 読み取れること

- **最大値**: 毎回回す人で 5年 45%・10年 69〜70%、1日1回の人で 10年 45%。「数年続けて一度出るかどうか」に合う。
- **16桁 (最大値以外) は、1年以内にほとんどの人が出す** (0.058% × 3,653回)。最大値の手前の壁は「16桁を出す」ではなく「最大値そのもの」になる。
- **同じ数字がほとんど出ない**: 10年で 36,530 回まわして種類数が約 27,500 (新しい数字が約75%)。「同じのが出過ぎてマンネリ」は起きにくい。
- **繰り上がりは少ない (10年で約650回)**: 同じ数字が10枚そろうのは1桁・2桁・3桁の一部だけ。1桁の数字は1つあたり約 1/105 なので、10枚そろうまで約1,050回 (約3か月)。主に1桁→2桁の入口で起きる。繰り上がりは「たまに起きるお楽しみ」になり、以前の分布より控えめ。
- **コレクション**: 10年で、1桁 (9種)・2桁 (90種) は完全にそろい、3桁 (900種) は 97%。4桁 (9,000種) は 29%、5桁以上は「点在」 (5桁で 3%)。画面では未解放の連続を省略して表示する。

## 5. コレクション画面の省略方法 (2案、切り替え可)

全 9×10^15 マスは並べられないので、2つの見せ方を用意した。画面上部のボタンで切り替え、選んだ方は保存される。

### 案A: 桁ごとに折りたたむ (初期表示)

- 1桁〜16桁の16個の折りたたみ。見出しに「解放数 / その桁の総数」と進み具合のバーを出す。
- 開くと、1〜2桁 (99個以下, `UI.fullGridMax`) は未解放も含めて全マスを表示。
- 3桁以上は、解放済みの数字だけマスで出し、間の未解放が **4個以上続くところは「🔒 a〜b 未解放 n 個」の1行** にまとめる (`UI.gapCollapse = 3`)。3個以下の小さな穴は未解放マスとして見せる (あと少しで埋まる感じが見える)。
- 解放済みが多い桁は 240種ずつ「さらに表示」(`UI.pageSize`)。
- 長所: 自分が持っている数字が一覧で見やすい。短所: 未解放の「広さ」は数字でしかわからない。

### 案B: 10進ズーム

- 最初は16桁分のタイル。タップすると、その範囲を10等分 (先頭の桁は 1〜9 の9等分) したタイルに絞り込む。表示は `3,4xx,xxx` のように、決まっていない桁を x で表す。
- 各タイルに「解放数 / 範囲の総数」とバー。何も持っていない範囲は暗い点線のタイル (未解放)。
- 最後の段 (10個) で数字のマスになる。どんな深さでも1画面は最大10タイル。パンくずが長くなったら途中を「…」に省略。
- 長所: 未解放の場所も含めて、9千兆の空間のどこに自分の数字があるかがわかる。短所: 持っている数字を見るのに何度かタップが必要。

## 6. 時刻と保存

- 更新番号 = floor((端末の現地時刻のミリ秒) / 12時間)。番号が前回より大きくなったら回数を5に戻す。
- 端末の時計を戻した場合は番号が小さくなるので、何もしない (回数は増えない)。進めた場合は回復してしまう。サーバーがないので防げない (README に記載)。
- 保存は `localStorage` の `numGacha.v1` 1つ。数字ごとに「手持ち (0〜9)・累計枚数・初入手時刻」を持つ。
- 抽選は `crypto.getRandomValues` の53bit (ない環境では `Math.random`)。

## 7. 決めた値と代替案

| 値 | 採用 | 理由 | 代替案 |
|---|---|---|---|
| 1桁の確率 | 約8.6% (shape 7 の結果) | 同じ数字が出過ぎてマンネリしない (5〜10%) | shape を 8 にすると約8.2%、6 にすると約9.1% (後半の落ち方が変わる) |
| 分布の形 | 桁ごとに確率を決め、前の桁との比が強まる | 小さい桁は平ら、最大値に向かって自然に絞られ、最大値の専用ルールが要らない | 等比 (shape 1。1桁を7%にすると最大値が約5%で出る) |
| 最大値の確率 | 1/30,000 | 10回/日で平均8.2年 (§2.3) | 1/20,000 (約5.5年、出やすめ) / 1/60,000 (約16年、より伝説的) |
| 同じ桁の中の確率 | 等確率 | 決め方が単純で、桁の確率とレア度が一致する | 小さい数字ほど出やすくする (決め方は複雑になる) |
| 更新時刻 | 現地 0:00 / 12:00 | 「12時間ごと」を時計の区切りにすると、残り時間がわかりやすい | 最後に回した時刻から12時間 (人によって時刻がずれる) |
| 最大値の繰り上がり | なし (枚数だけ増える) | 上限より上の数字は存在しない | 10枚で「MAX+」の称号を出す |
| レア度の区切り | 1-4 / 5-7 / 8-9 / 10-11 / 12 / 13 / 14-16桁 + MAX | 確率が 1/3 → 1/4 → 1/6 → 1/7 → 1/21 → 1/33 → 1/55 と開く | 桁ごとに16色 |
| 未解放の省略 | 4個以上の連続を1行に | 3桁の帯でも「あと少し」の穴は見え、長い空白は1行になる | 常に1行にまとめる (`gapCollapse: 0`) |

## 8. 画面の構成 (スマホとパソコン)

- **スマホ (幅 960px 未満)**: 縦に並べてスクロール。コレクションは「桁ごとに折りたたむ」か「10進ズーム」。
- **パソコン (幅 960px 以上、高さ 560px 以上)**: ページ全体はスクロールせず、1画面に収める。
  - ガチャ: 左に演出の玉と「まわす」ボタン、右に集計 (解放した数字・最大の数字・まわした回数・繰り上がり)、最近出た数字、提供割合を常に表示。
  - コレクション: 左に集計と最大値と16桁の一覧 (桁ごとの進み具合)、右に選んだ桁の中身。一覧が1画面に全部見え、数字の一覧だけが右の枠の中でスクロールする。「10進ズーム」は右の枠に出る。
  - 画面サイズの切り替えは、ウィンドウの大きさを変えるとその場で切り替わる。
